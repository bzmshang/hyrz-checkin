# 火影福利站 · v9.16.1 本机诊断版

v9.16.1 修正手动运行窗口只有 `Script done` 的显示问题：点「火影·只读诊断」，在结束标记之前会打印版本标记、结论及脱敏状态码。不会发起签到、领奖或推送；保留 v9.16 已有的本机会话。

已订阅原 GitHub 或 jsDelivr 地址的用户，在 Loon 的「插件」页刷新即可，无须删除或重新导入。到「脚本」点「火影·只读诊断」，结果应显示 v9.16；如果还是旧版，请等缓存刷新后再试，不要同时启用两份。**先验证基本签到，再开启奖励等可选功能。** 本版本经过离线回归，尚未经你的账号真机验证。

## 安装与首次使用

见 [安装说明](docs/install.md)。需 Loon **3.5.1 (983) 或以上**；同一时间只启用一份插件，先停用旧版，不必删旧版或清空 Loon 全部数据。v9.16 的清单与两份 JS 要配套。若同机用本项目提供的 `python3 tools/serve_local.py`，该命令仅在回环 127.0.0.1:18916 提供三个安装文件，不提供账号数据或执行签到，约 1 小时后退出；需要时可重新启动。长期使用建议部署到自己控制的、能稳定访问的 HTTPS 地址。

1. 在插件参数里确认 `claimGift`、`autoTasks`、`catchup`、`uploadLog` 都关闭，`logTopic` 为空，签到流程保持默认。升级保留旧参数的设备尤其要检查。默认 09:00 的每日签到仍独立启用。不要设置额外的微信公众号、游戏域名通配解密。
2. 保持 Loon 的代理、脚本和对应两域名的 HTTPS 解密可用。用**本人账号**打开微信里的福利站签到页，等到页面能显示今天「已签／未签」，**先不点签到**。新版本故意不读旧会话和旧日志，无需导出或手填 Cookie；插件不会自行登录或续票。
3. 到 Loon 脚本列表点 **火影·只读诊断**。这是对已有状态的单次查询，不会签到或领奖，也不推送。比较结果与小程序。如果都明确显示未签，可点 **火影·手动签到** 一次，再刷新小程序看结果；显示已签、状态不一致、或者限流时不要强发。手动补领是另一项操作，不适合作为签到诊断。
4. 反馈时只贴 v9.16 的文字摘要。不要发抓包、请求体、Cookie、token、g_tk、openid、角色 ID、频道名或旧版「服务端原文」。

```text
Loon 版本/build：
几点打开小程序？当时显示：已签 / 未签
只读诊断：结论、查状态的 HTTP / 顶层 / 流程 / 业务数字
最近捕获：时间、类型；会话/身份/校验字段：有 / 无
若运行了手动签到：动作与复检摘要；刷新小程序后：已签 / 未签
若只有定时失败：火影·看日志 → 最近每日定时的时间和结论
```

- **无捕获时间**：先核对脚本版本、证书信任、插件命中、Loon 运行状态；活动或请求路径变化也会导致不命中，不能直接判断 token 已过期。
- **有捕获但会话缺失／过期**：确认小程序页面已登录、重新进入签到页。若仍缺就反馈摘要；不要手工迁移旧凭据。
- **HTTP 非 2xx、限流、返回无法识别、业务错误**：不是同一种故障。先保留状态码；不探测新流程号，不扩大采集范围，也不要连续点击。
- **只读正常、手动成功但每日没跑**：对照「最近每日定时」、时间设置和 Loon 运行记录，而不是重抓登录态。

## 操作语义

| 入口 | 行为 |
|---|---|
| 火影·看日志 | 纯本机，显示最近几次运行、捕获、上次每日 Cron 的时间与结论，不读旧日志或网络频道 |
| 火影·只读诊断 | 有可用会话才发一次已知 AMS 状态查询；不发签到、礼包或活跃请求 |
| 火影·手动签到／每日签到 | 查到明确未签才提交一次，再通过独立状态查询确认是否已签；状态未知不写、未复核不报成功。手动签到不做活跃任务 |
| 火影·手动补领 | 先核对并在明确未签时签到，再只领面板明确可领的活跃奖励；手动操作会重新查面板 |
| 可选定时补领 | `catchup` 开启后，刷新会话留下本机待办，约每十分钟检查；另有每天五次 :05 错峰兜底。不是打开小程序就同步领取，也不依赖 `autoTasks`。iOS／Loon 实际调度决定延迟 |
| 可选礼包／活跃 | `claimGift`：签到等入口顺带领礼包；`autoTasks`：每日签到顺带领已达成的活跃奖励。**不代报浏览或点赞等任务，不保证拿满100分。** |

## 这版解决的问题与边界

- 只在已知活动和 HTTPS 路径接收会话；本机只存运行所需字段，换身份或角色不混用状态。新记录使用 `hyrz_v916_` 键，**不会自动清除旧版留在 Loon 或 ntfy 的数据**。不要用清空全部持久化存储来排查本插件。
- 网络响应只在内存解析，日志/结果不复制服务器正文、错误字符串或账户字段。自愿启用 ntfy 时，仅自动任务发送一条固定结论，不发日志、无频道缓存、失败不重试；手动/异常路径不默认外发。所有脚本外发请求显式校验证书、不跟随跳转。移除网页写频道、强制签到、假流程对照和自请求补领入口。
- 同一写入入口先取得本机短期执行标记，提交前记录当天/当前身份的尝试，十分钟内不重复提交签到。Loon 持久化没有事务，这只降低并发概率，不是跨进程的严格互斥；不要同时启用主/备两个插件。
- 礼包错误不等于空列表；100 分不等于三个宝箱都已领。只领取服务端明确标为可领的项目，写操作不就地重试，限流、字段变化或耗时过长就停止。下次符合条件时重新查询，无需盲试或规避频控。
- 活动、状态字段和流程默认值沿用审计基线。没有新真机证据前，不宣称腾讯未改接口，也不猜新流程 ID。如果配置显示 v9.16 但脚本结果没有版本号，先排除脚本缓存或新旧混装。

node --check hyrz-sign.js && node --check hyrz-sniff.js

这些测试使用合成字段、内存存储和替身网络；没有访问游戏接口，没有代表用户签到。回滚：停用 v9.16；若必须回到旧版，仅启用一份旧清单，注意其已知日志隐私风险。
