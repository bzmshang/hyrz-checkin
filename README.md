# 火影忍者福利站 · 自动签到（Loon 插件）

每天定时自动完成「火影忍者手游 · 微信小程序 福利站」签到并领取福利站礼包。
保持 Loon 开启、打开一次微信小程序，登录态会自动抓取（票据 24 小时，会自动续期）。

也可以手动做：Loon 的「脚本」列表里有三个手动按钮 —— **火影·手动签到** / **火影·手动补领** /
**火影·看日志**（v9.12 起）。点一下就跑，结果（含脱敏原文和日志）直接出在 Loon 内的页面里，
**不跳浏览器、也不用输网址**；页面里还有按钮可以在「签到 / 补领 / 看日志」之间来回切。

作者：**Bzmshang** · 当前版本：**v9.13**

## 一键导入

主地址（GitHub）：

```
loon://import?plugin=https%3A%2F%2Fraw.githubusercontent.com%2Fbzmshang%2Fhyrz-checkin%2Fmain%2Fhyrz-checkin.plugin
```

备用（jsDelivr，GitHub 打不开时用）：

```
loon://import?plugin=https%3A%2F%2Fcdn.jsdelivr.net%2Fgh%2Fbzmshang%2Fhyrz-checkin%40main%2Fhyrz-checkin-jsdelivr.plugin
```

导入后在 Loon → 插件 里就是开启状态。如果之前装过旧版、列表里出现两条，
把旧的那条开关关掉即可（不用删）。

## 手动按钮（v9.12，推荐用这个）

Loon → 「脚本」列表里点一下就行，不用打开浏览器：

| 按钮 | 做什么 |
| --- | --- |
| 火影·手动签到 | 立刻跑一次「查状态 → 签到 → 复检 → 领礼包」，结果直接印在 Loon 内的页面里 |
| 火影·手动补领 | 同上，再把「活跃任务」做到小程序里能做的上限（上报查看类 + 逐项领奖励 + 开积分宝箱） |
| 火影·看日志 | 列出最近 48 小时的频道日志 + 本机日志尾巴（频道名没填就只看本机日志） |

页面顶部三个按钮可以来回切；日志页还能只看签到或只看补领。这三条是 `generic` 脚本，`argument` 是
写死的字面量（`now=sign` / `now=task` / `now=log`），所以这一跑用**参数默认值** + 本机缓存的频道名；

> Loon 的**插件页**只能放开关 / 下拉 / 输入框，放不了按钮 —— 所以「点一下就跑」的入口做成这种
> 手动脚本，放在 Loon 的「脚本」列表里（v9.12 起）。

## 手动签到（浏览器入口，仍然保留）

不想等定时任务，想在浏览器里立刻验证一条龙时，用 iPhone 的 Safari 打开：

```
https://ulinkact.game.qq.com/hyrz-sign-now
```

脚本会当场跑一次（查状态 → 签到 → 复检 → 领礼包），并把结果写在网页上；
今天已经签过就跳过，不会重复发签到请求。

想看服务端到底回了什么（排查用）：

```
https://ulinkact.game.qq.com/hyrz-sign-now?force=1
```

这个会**就算今天已经签过也再发一次签到流程**，并把服务端原文（已脱敏）贴在网页上；
同时还会拿一个不存在的流程号（999999）打一条对照请求：两条返回不一样，说明服务端认得签到流程，
这说明签到真的有效；两条一模一样，就说明这次请求本身没被服务端认（多为登录态/参数问题），
不能据此判断流程号对错。两种链接结果都会同时弹一条通知、也发到你的日志频道。

> 这两个地址只是「把已经抓到的登录态用一次」，不会上传任何东西到外部服务器。

## 手动领活跃任务（v9.4）

福利站里还有个「活跃任务」面板（看帖子 / 点赞 / 看金币助手…攒积分开宝箱）。用 Safari 打开：

```
https://ulinkact.game.qq.com/hyrz-task-now
```

它先跑一遍上面那条龙（查状态 → 签到 → 复检 → 领礼包），接着处理活跃任务：

- **能直接领的**（还能领且进度已够）：用真实的领取接口 `Index/taskLotteryNow` 一次领掉，领到哪几项、
  加了多少活跃积分都写出来（服务端要嫌参数不对，会自动带上任务键再试一次）；
- **只需「点开一个页面」的查看类任务**（动态 / 金币助手 / 浏览记录 / 活动日历 / 壁纸 / 忍者 / 客态资料
  这 7 项）：帮你上报一次完成状态，进度够了就顺手领掉。不想做这一步（只领已经能领的）就用
  `https://ulinkact.game.qq.com/hyrz-task-now?report=0`（看帖子 / 点赞这两项服务端不收上报，只能在
  小程序里真的去读 / 去点赞）；
- **积分宝箱**：今日积分够 40 / 60 / 100 时，把对应宝箱开掉（以服务端给的今日积分为准）。

做不了的三类：绑定手机号（要短信验证）、决斗场（得真打赢）、游戏内活跃度≥80（得去玩游戏）——
这几项会自动跳过，页面里会说清楚。

老规矩：每条接口之间停 0.25 秒，遇到服务端限流立刻收手并把原话解成中文写出来；所有「领到了什么」
只信服务端的回答（`iRet=0` 才算成），不把「已领过 / 不可领」谎报成成功。

页面最下方还有两段诊断（日志频道一直没动静时先看它们）：

- `日志上报：开｜频道名：已设（尾 xxxxxx）` —— 上报开关与频道名到底有没生效；
- `本机日志尾巴` —— 抓包脚本记下的最近 20 条请求（含小程序自己发的），一眼看出是脚本没跑、
  还是小程序那边请求本身就没抓到。

> 频道名可以直接存在本机：用 Safari 打开 `https://ulinkact.game.qq.com/hyrz-sign-now?topic=你的频道名`，
> 两个脚本共用这个值，以后升级插件不用再填（频道名只在本机，绝不进仓库）。

> 想让它跟着每天定时任务一起做，把插件参数 `autoTasks` 打开。默认是关的：定时任务只签到 + 领礼包。
> v9.8 打开后，定时任务会连「只需点开一个页面」的查看类任务一起上报、把能领的领掉、够门槛的宝箱开掉，
> 并在通知头上写一行 `活跃 X/100`，跑完一眼就知道小程序这边够不够 100 分（第 3 个宝箱的门槛）。

> **v9.11 起**：发奖接口只认「**当天**在小程序里刷新过的登录态」。登录态不是今天的，脚本就不去白碰
> （免得白挨一顿 `4414`），只在通知里写一行 `活跃待补领（登录态要刷新）`。你在小程序里随便点一下刷出
> 今天的登录态之后，`12:00` / `21:00` 两条补领任务会把当天没领的奖励补齐 —— 跑完只在真领到东西时才
> 通知，什么都没领到就只写一行日志（不打扰）。抓包脚本抓到「今天的登录态」而当天还没领满时，只记一行
> 补领日志（**v9.13 起不再弹「该补领了」通知** —— 这一跑的前提本来就是「你人已经在小程序里了」，
> 再弹一条纯属多余；想马上补齐就去 Loon 的「脚本」列表点「火影·手动补领」）。

## 参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| cronTime | `0 9 * * *` | 每天签到时间（cron：分 时 日 月 周） |
| signFlow | `1083576` | AMS 签到流程 ID（实测的签到动作）；填 `1083547` 或留空都按 1083576 处理 |
| claimGift | 开 | 自动领取福利站礼包 |
| autoTasks | 关 | 定时任务顺带做「活跃任务」（v9.8 起含：上报查看类任务 + 逐项领任务奖励 + 开够门槛的积分宝箱）；手动按钮 / 手动页不受这个参数影响 |
| catchup | 开 | 刷新登录态后自动补领（v9.11）：`12:00` / `21:00` 各跑一次补领（当天已经领满就直接跳过、不发通知），并且在抓到「今天的登录态」而当天还没领满时记一行补领日志（一天最多一行；**v9.13 起不再弹「该补领了」通知**）；关掉则两条补领任务直接跳过、也不记补领日志 |
| uploadLog | 开 | 把脱敏日志推到你自己的频道（在 Loon 的「脚本」列表里点「火影·看日志」就能看） |
| debug | 关 | 每收到一个福利站请求弹一条通知（确认插件是否生效用） |
| logTopic | 空 | 私密日志频道名（ntfy），只填在本机、不要外传；留空则只在本机记日志（也可以用 Safari 打开一次 `…/hyrz-sign-now?topic=频道名` 把频道名存到本机） |

## 日志在哪看

日志推到你自己的私密频道（ntfy），频道名填在插件参数 `logTopic` 里、只保存在本机，
本仓库里没有。**v9.12 起通知不再挂跳转链接** —— 想看日志就去 Loon 的「脚本」列表点
「火影·看日志」（页面里直接列出最近 48 小时的频道日志；消息在频道里保留 12 小时）。

日志里能看到每一步：抓到登录态、签到流程请求、礼包领取结果、活跃任务的面板与领取（含开宝箱）结果，
以及上报失败的原因。如果出现 `⇦ 脚本 v9 已生效（响应阶段）`，说明「记录领取结果」
这段真的在跑。每批日志开头也会带上脚本版本号（如 `脚本 v9.13`），手动按钮的页面同样会印版本号
（`脚本 v9.13`），用来确认本机拿到的是不是最新那一版。

## 说明

- 只上报脱敏后的日志：token / g_tk 全部打码，openid 只留前 4 位与后 3 位，角色 ID 只留前 2 位与后 2 位。
- 抓包只针对 `x8m8.ams.game.qq.com` 和 `ulinkact.game.qq.com`。
- 日志只存在本机（Loon 持久化存储）+ 你自己填的频道，不往别处发。
- 本仓库只托管插件与脚本：不含账号信息、不含 token、不含日志频道名（每推一次都会自检）。
- 登录态不是「今天」刷的就只读不写：签到 / 礼包照旧，发奖接口（领任务奖励、开宝箱）整段跳过，避免白挨 `4414`。

- **v9.7**：修掉「活跃任务一直没领到」的真正根因。领任务奖励要**逐项带上任务键**
  （`Index/taskLotteryNow&index=<任务键>`），服务端一次只认一项；而不带 `index` 时服务端回的是
  **`1228`「index参数范围不对」**（`jData` 里也写着）—— 不是上一版假定的 `1226`，所以旧版那个
  「先不带、只有回 1226 才带上 index 再试一次」的判断永远走不到带 index 那一步，每项都被服务端挡回。
  2026-09-27 12:16 让用户在小组序里手点一下「今日签到」，日志里当场看到真实形状：
  `Index/taskLotteryNow&index=sign → iRet=0「领取任务奖励成功」`，今日积分 0 → 10。现在逐项带键
  去领、成功一项加它自己的 `pointNum`、领到什么写什么；同一种失败只印一行（带服务端原话），
  绝不把没领到的说成领到了；积分宝箱仍走 `Welfare/getTodayActGiftNow`（`index=0/1/2`），
  且只在积分够门槛时才去碰。
- **v9.6**：把「领活跃任务」改回真实抓包里的 `Index/taskLotteryNow`。上一版用的是
  `Welfare/getTodayActGiftNow` —— 它是**积分宝箱**的接口（09-25 抓包里今日积分 70 时正好被调了 2 次，
  就是门槛 40 / 60 的两个宝箱），拿它按任务键去领，服务端一律回 `4027 无活跃度不能领取奖励`，这就是
  上一版任务没领到的原因。现在顺序是：面板 → 领任务奖励（不带参数，服务端要嫌参数不对就带上任务键
  再试一次）→ 积分宝箱 → 回报今日积分变化。另外两处：上报查看类任务去掉 `readArticle` / `like`
  （服务端对这两个回 `1226`，只能在小程序里真的去读 / 去点赞）；手动页多两段诊断
  ——「日志上报」状态行和「本机日志尾巴」，并提供 `…?topic=你的频道名` 一键把频道名存进本机。
- **v9.5**：修一个把服务端「正常返回」误判成「顶层挡回」的 bug，这是上一版活跃任务没能真正生效的原因。
  福利站接口的正常返回长得像 `{"iRet":0,"sMsg":"ok","jData":{…}}`（没有 `modRet`），而「顶层挡回」的判断只
  看「没有 `modRet` 但有 `sMsg`」→ 拉回来的面板第一眼就被当成被挡回，整段活跃任务直接跳过（2026-09-27
  09:36 真机实测：页面写着「服务端顶层挡回（ret=无｜ok）」）。现在只认真正带 `ret` 且非 0 的响应，带
  `jData` 的一律按正常返回处理；手动页并多印一行「任务进度」，每项做到哪、能不能领一眼可见。
- **v9.4**：新增「领活跃任务」（上面那一节）。福利站那个「活跃任务」面板里，能直接领的用福利站自己的
  接口一项项领（领到什么写什么），够门槛的积分宝箱（40 / 60 / 100）顺手开掉，手动页还会替你把「只需点开
  一个页面」的查看类任务上报一次（不想要就加 `?report=0`）。绑定手机号 / 决斗场 / 游戏内活跃度这三类
  做不了，页面会明说跳过；遇到限流会立刻收手。定时任务默认不碰它，要用就把参数 `autoTasks` 打开。
- **v9.3**：修掉一个抓包时才会遇到的坑。同一个登录会话里，小程序有些请求会带着「更旧的一次登录
  会话」（票据到期时间更早）；旧版的抓包脚本是谁最后来就存谁的，哪怕它更旧，于是刚抓到的好票据会被
  顶掉。2026-09-26 就是这样：上午 09:11 抓到的票据有效到 09-27 09:05（正好够第二天早上签到用），
  09:45 被一张 09-26 15:07 就到期的旧票据顶掉，第二天 09:00 的定时签到只剩一句「票据已过期，跳过」
  ——白等一天。现在票据更旧就不覆盖（同时在用的票据若已经过期，则照样收下新的）。日志里会写一行
  「忽略了一次更旧的登录态…」，一眼能看出它做过什么。
- **v9.2**：服务端报错不再是天书。AMS 的报错文案是 `\uXXXX` 转义的中文（真机上看到的就是一大片
  `\u76ee\u524d…`），现在会先解成中文再显示（手动签到页面、日志、通知都改了）；并且能认出「服务端连
  流程引擎都没进、直接在**顶层**挡回」这种响应（例如 `ret=-1`「目前访问数过多！请稍后再试！」）——
  这只说明服务端在限流/防刷，跟脚本、跟流程号都没关系，页面不会再据此给出「流程号已验证」的错误结论；
  一旦发现是限流，脚本干脆连签到请求都先不发，免得越打恢复越慢。
- **v9.1**：新增「手动签到」（上面那一节）。用 Safari 打开 `https://ulinkact.game.qq.com/hyrz-sign-now`
  就能立刻跑一次签到，不用等第二天早上；`?force=1` 会今天已签也强制重发一次，
  并把服务端原文 + 对照用的假流程结果一起贴在网页上——这是为了能在当天就验证签到流程号对不对。
  自动签到一点没变，仍然按 `cronTime` 跑。
- **v9**：修掉「定时任务跑了但没签到」的真凶——签到状态查询（1083547）和真正的签到动作是两个不同的
  流程号，而旧版的参数默认值正好填成了状态查询流程：脚本只会查两遍状态、根本不发签到请求，于是通知
  一直显示「今日未签到」（2026-09-26 早上那一次就是这样，日志里干干净净、一个签到请求都没有）。
  现在默认改成实测抓到的签到动作 **1083576**，并且只要今天还没签就把签到请求发出去；参数里留着旧值
  或留空都会按 1083576 处理。签到后以复检结果为准，通知里会写「签到：成功 ✅」或带上服务端原话
  （iRet / sMsg），出问题时一眼能看出下一步该改什么。
- **v8**：上报加自动重试。ntfy 在境外，TLS 握手偶尔会被网络环境打断（真机上有一批 5 片日志，
  前 3 片就是这么丢的；丢完脏标记还在，下个请求会把整批日志再推一遍，于是频道里出现重复）。
  现在传输层报错（TLS 握手失败 / 超时）或 5xx 会就地重试最多 2 次（间隔 0.4s / 0.8s），重试成功
  就不算失败；连 3 次都不行才记一行 `✗ 上报失败` 并弹通知，通知里只显示一句人话
  （例如「TLS 握手被网络打断（环境抖动）」），原始报错照样写在日志里。
- **v7**：修掉「同一批日志被推好几遍」的真凶——Loon 给每个请求一个独立上下文，同一秒里几个
  请求同时命中时，几个脚本各自「先读标记、再写标记」，谁都没看到别人的标记，于是各推一遍
  （真机上同一批日志出现了 4 份）。现在改成先等 0.3~0.9 秒、再复查一次标记，谁复查通过谁推。
  另外：只有 ntfy 明确回 4xx（格式/体积不对）才改发纯文本；TLS 握手失败/超时不再改发
  （那条请求其实已经送达，再发一遍就是重复推送，v6 真机上 16:58 那几条就是这么来的）。
  还有：抓包脚本刚推过时，签到脚本不再重复推、也不弹「日志没推上去」的假告警。
- **v6**：修掉最后两个上报隐患——① 中文日志原来按「字符数」分片，中文 1 字 3 字节，
  超 4KB 会被 ntfy 拒（413），现在按 UTF-8 字节分片；② JSON 发布失败时的纯文本兜底原来发到
  根地址 `https://ntfy.sh/`，而根地址只收 JSON，必然 400，于是日志其实传上去了还会弹
  「上报失败」——现在兜底发到自己的频道地址。另外同一秒里连发几个请求只会推一次（不再重复推四五遍）。
- **v5**：隐私收紧——日志频道名不再写在仓库里（改成插件参数 `logTopic`，只存本机）；
  上报日志里的角色 ID 也打码；推仓库前逐字自检，命中私人数据就直接不上传；
  没填频道名时只在本机记日志、不报错。
- **v4**：修掉「上报失败」误报——响应阶段改成先把上报发出去、再同步放行，
  不再在 Loon 释放脚本上下文之后发请求；广告/首页轮询等噪音接口不再进日志；
  上报失败的原因会写进日志；新增「脚本已生效（请求/响应阶段）」标记。
